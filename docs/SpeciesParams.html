3  Species parameters

Gathering needed species parameters is probably the biggest job in building a mizer model, particularly if you’re working with poorly understood species in a data-poor region. Working with a team makes the job easier1. It also helps that mizer will estimate many parameters for you based on sound science. See their site for more.

To start, we gathered the parameters listed in Table 3.1 by consulting the corresponding references listed in Table 3.2. While these tables look nice and tidy, there was ample background work involved. Our team had a shared Google doc where we noted parameters and left helpful feedback for one another. The final parameters were added to a data frame using a script, although you could absolutely do this step in the spreadsheet editor of your choice (and it would probably be easier).

In Table 3.1, the NA values for weight-related parameters (e.g., w_mat, w_max) indicate weights that are converted from lengths using the a and b parameters. NA values for a and b parameters indicate sexually dimorphic species. In these cases, weights are calculated for each sex and then averaged. NA values for length-related parameters (e.g., l_mat, l_max) indicate species for which the corresponding weights were available without conversion. These NA values all carry through to Table 3.2.

In Table 3.2, default indicates parameters that were estimated following the prior methodology:

  • w_min: all teleosts enter at 1 mg
  • R_max: scaled from maximum body size as 1011 \(\times\) wmax-1.5 (Blanchard et al. (2014))
  • w_min: species’ minimum depth is 0 m in the absence of evidence to the contrary

Expert Opinion notes rare instances when insufficient data were available in the literature and the authors used their best judgement based on information available for similar species and/or life history parameters. Each species’ minimum and maximum depths (depth_min and depth_max, respectively) were used by a script to build the interaction matrix (Table 3.3) based on vertical overlap (see the original model for more details). These depth ranges were typical depth ranges, not record observations, because we want species’ typical overlap.

We include the following species in our model:

  • Lancetfish (Alepisaurus ferox)
  • Bigeye Tuna (Thunnus obesus)
  • Blue Shark (Prionace glauca)
  • Mahi Mahi (Coryphaena hippurus)
  • Swordfish (Xiphiaus gladius)
  • Yellowfin Tuna (Thunnus albacares)
  • Skipjack Tuna (Katsuwonus pelamis)
  • Albacore Tuna (Thunnus alalunga)
  • Striped Marlin (Kajikia audax)
  • Wahoo (Acanthocybium solandri)
  • Opah (Lampris guttatus)
  • Blue Marlin (Makaira nigricans)
  • Shortfin Mako Shark (Isurus oxyrinchus)
  • Pomfret (species complex, see below)
  • Shortbill Spearfish (Tetrapturus angustirostris)
  • Oceanic Whitetip Shark (Carcharhinus longimanus)
  • Snake Mackerel (Gempylus serpens)
  • Escolar (species complex, see below)

Note that both pomfret and escolar are species complexes due to changes in observer reporting over time. We leaned towards drawing upon references for the dominant species in each group wherever possible.

We used the following species parameters:

  • species: names for each species in the model, keep these in the same order across all your code and data
  • w_max: maximum mass in grams for each species, generally observed maximum rather than asymptotic
  • w_mat: mass in grams at maturity, we use \(W_{50}\)
  • age_mat: age in years at maturity
  • w_min: minimum mass in grams
  • R_max: maximum reproduction rate
  • depth_min: typical minimum depth in meters
  • depth_max: typical maximum depth in meters
  • beta: preferred predator-prey mass ratio
  • sigma: width of the lognormal feeding kernel
  • a: length-weight conversion factor, used as \(W = aL^b\)
  • b: length-weight conversion factor, used as \(W = aL^b\)
  • l_min: minimum length in cm
  • l_mat: length at maturity, we use \(L_{50}\)
  • l_max: maximum length in cm, generally observed maximum rather than asymptotic
  • catchability: see Chapter 4

Note that this list of parameters doesn’t exactly match those used during in the prior model due to updates to the mizer model itself. See the mizer site for further details and additional parameters.
